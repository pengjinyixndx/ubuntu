## 一、你定死的规则

- **谁是谁**：先注册的是「小螃蟹（他）」，后注册的是「银杏叶（她）」。名字就这两个，**不做改名入口**。
- **自己删 vs 后台删**
  - 自己删：软删，**双方都看不到**；本人可在「我的 → 恢复」里恢复；**后台一直看得见**
  - 后台删：直接删行，**双方都不知情**，不可恢复
  - **满 90 天**由定时任务真删（连图片文件）
- **哪些能自己删**：只有**文字类（随笔/日记）和照片类**
  - **不能删**：请求类（奶茶请愿）、亲亲
- **后台**：新增「被用户删除的内容」页
- **实时**：要（对方一发这边立刻收到）
- **通知**：先做 App 内提醒；系统推送（Web Push）以后再说（iPhone 必须加到主屏 + iOS 16.4+）
- **「我的」页新增**：恢复、历史矛盾

## 三、已知的坑（写下来免得重犯）

1. **我（AI）连不上 Supabase** —— 所有"验证通过"都是内存演示数据（mock）跑的，
   **真库链路只能靠你点**。这次的删除 bug 就是这么漏的。
2. **RLS 拒绝时 PostgREST 不报错、只是一行没动** —— 所以写操作一律
   `.select('id')` 把影响的行取回来数，为 0 就报失败，不能只看 `error`。
3. **模块级单例（useFeed / usePetition）换账号必须 reset**，
   否则新登录的人看到上一个人的档案。
4. **不要把手动配置当默认**（早期的 gender 就是这样，
   数据库空着就两个账号都成了同一个人）。能自动判定的就自动判定。
5. PowerShell 搜中文不可靠，查打包产物要用 Node 按 UTF-8 字节搜。
